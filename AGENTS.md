# AGENTS.md

## Проект/стек

- **Название проекта:** my-opencode-project
- **Репозиторий:** https://github.com/HeleonoraQA/my-opencode-project.git
- **Суть проекта:** конфигурационный скелет для OpenCode. В репозитории нет прикладного исходного кода — только настройки агента, права доступа, навыки, тесты и документация.
- **Стек:** Node.js (ESM), Vitest, ESLint, Husky, GitHub Actions
- **Ключевые элементы:**
  - `opencode.json` — конфигурация OpenCode V2 (`instructions`, `permissions`, `policies`)
  - `rules.md` — жёсткие правила проекта (подключены через `opencode.json`)
  - `src/permissions.js` — матчер прав доступа (last-match-wins, `*`/`?`)
  - `.opencode/skills/` — навыки агента (`lint`, `run-tests`)
  - `.opencode/plugins/` — плагин V2 `lint-and-guard` (автолинтер в `tool.hook("execute.after")`, блокировка защищённых путей в `tool.hook("execute.before")`)
  - `tests/` — тесты конфигурации, структуры и прав доступа
  - `docs/` — документация проекта (`plan.md`, `memory.md`, `about.md`)
  - `.husky/` — Git-хуки (`pre-commit`, `pre-push`, `commit-msg`)
  - `.github/workflows/ci.yml` — проверка в GitHub Actions

## Команды

- Установка зависимостей: `npm install`
- Запуск всех тестов: `npm test`
- Запуск e2e-тестов: `npm run test:e2e`
- Запуск тестов в режиме наблюдения: `npm run test:watch`
- Проверка линтером: `npm run lint`
- Исправление ошибок линтером: `npm run lint -- --fix`

## Конвенции

- **Сообщения коммитов:** соблюдать Conventional Commits — `type(scope): summary`. Допустимые типы: `feat`, `fix`, `docs`, `chore`, `refactor`, `test`, `ci`, `build`, `perf`, `style`. Исключения: `Merge`, `Revert`.
- **Стиль кода:** использовать ESM. Код проверяется `eslint` по правилам `no-unused-vars` и `no-undef`.
- **Тестирование:** при изменении конфигурации, документации или тестов обязательно запускать `npm run lint` и `npm test`.
- **Документация:** при изменении правил, прав доступа или структуры проекта обновлять `AGENTS.md` и `docs/memory.md`.

## Правила работы

- **Доступ к файлам:** `.env`, `.env.*`, `*.key`, `*.pem` и содержимое папки `secrets/` — полный запрет на чтение и изменение. Обойти нельзя. Перед любыми файловыми операциями необходимо проверять, не попадает ли путь под этот запрет.
- **Реализация запрета (OpenCode V2):** глоб-паттерны в `permissions` — `*.env`, `*.env.*`, `*secrets/*`, `*.key`, `*.pem` для `read` и `edit` (в V2 `*` совпадает и с `/`, поэтому правило действует на любой вложенности; префикс `**/` не нужен и не покрывает корневой `.env`). Дополнительно тот же набор продублирован в `policies` как `tool.use` → `deny`: policy-запрет не перекрывается сохранёнными разрешениями «Allow always» и правилами агентов. Плагин `lint-and-guard` дополнительно блокирует эти пути в `execute.before` (защита в глубину).
- **Операции с файлами:** правка, создание и другие операции с файлами требуют подтверждения.
- **Права shell:** по умолчанию любая команда требует подтверждения. Без подтверждения разрешены только `git *` (кроме `git push` — он всегда `ask`), `npm test`, `ls *`.
- **Автоматические проверки:** `pre-commit` запускает только `npm run lint` (навык `lint` — автоматический). `pre-push` запускает `npm run lint && npm test`. GitHub Actions (`.github/workflows/ci.yml`) запускает `npm run lint && npm test` при `push` и `pull_request`. Соблюдение Conventional Commits проверяется хуком `commit-msg`. Дополнительно плагин `.opencode/plugins/lint-and-guard/` после успешного `write`/`edit`/`patch` запускает `eslint --fix` по изменённому `.js`-файлу (остальные расширения не покрыты `eslint.config.js`), а в `execute.before` блокирует файловые инструменты на защищённых путях. Линтер запускается через `node` из PATH: `process.execPath` в рантайме OpenCode — это `opencode-cli.exe`, а не Node. Правки самого плагина применяются после перезапуска локации/приложения: горячая перезагрузка оставляет плагин `active`, но хуки в уже запущенной сессии не срабатывают. Основная защита секретов — `permissions` + `policies` в `opencode.json`: настроенный `deny` не доходит до хуков.
- **Навыки:** `lint` — автоматический (запускается через хук `pre-commit` после редактирования), `run-tests` — ручной (вызывается только по команде пользователя).
- **Безопасность:** никогда не коммитить секреты, ключи, `node_modules` и артефакты сборки.
- **Изменения вне проекта:** не изменять файлы за пределами проекта.
- **Опасные команды**: Команды, изменяющие удалённый репозиторий (например, `git push`), а также любые команды, не входящие в список разрешённых, требуют явного подтверждения пользователя.
- **Режим по умолчанию**: Все bash-команды по умолчанию требуют подтверждения (`ask`). Разрешены без подтверждения только безопасные команды чтения (`git status`, `git diff`, `git log`), просмотр файлов (`ls`) и запуск тестов (`npm test`).
